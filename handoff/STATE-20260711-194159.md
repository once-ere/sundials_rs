## 1. ARKODE architecture in this port

- `ARKodeMem` (arkode_impl.rs): ~55 `Option<fn(&mut ARKodeMem, ...)>`
  step_* ops installed by each stepper's Create, exactly like C's
  fn-pointer table.  `step_mem: Option<Box<dyn Any>>`, downcast by the
  owning stepper via `<stepper>_AccessStepMem` (TAKE semantics: take the
  box out, run an `_inner` worker, put it back — every wrapper follows
  this; early returns must put back).
- Only field rename in the whole crate: C `fn` -> Rust `fn_`.
- `ycur` OWNS storage (C aliases user's yout); ARKodeEvolve copies
  ycur->yout at every return path.  `rwt_is_ewt` => rwt left unallocated.
- `efun = None` => internal dispatch (arkEwtSetSS/SV via itol).
  Steppers that force SmallReal install a local 3-arg shim
  (`erk_ewt_small_real` / `lsrk_ewt_small_real` pattern) because the
  ARKEwtFn type takes (y, w, e_data).
- ARKLS: `lmem: Option<Box<ARKLsMem>>` and
  `mass_mem: Option<Box<ARKLsMassMem>>` are HOISTED onto ARKodeMem
  (C keeps them behind the stepper's void*) — Addendum C.1/C.2.
  step_getlinmem/step_getmassmem ops have take semantics; put-back
  writes the field.  `step_setjcur` is a Rust-only companion op
  (write-back for the pset jcur pointer C hands out via getgammas).
- Fn-pointer "data pointer" collapse: C's J_data/Jt_data/P_data/A_data/
  M_data/mt_data/e_data all collapse onto `ark_mem.user_data` or flag
  conventions (`jac: None + jacDQ` => internal DQ, etc.).
- Iterative solves (system LS, mass LS, DomEig estimate) build their
  ATimes/PSolve closures per call over `RefCell<&mut ARKodeMem>`
  (donor cvode_ls pattern).  KEY BUG CLASS FIXED TWICE: anything the
  closure needs that was `std::mem::take`n out of ark_mem (ewt for
  scaling vectors!) must be passed into the helper as an argument —
  see arkLsDQJtimes signature.
- NLS: solve loops are INLINED per stepper (arkode_arkstep_nls.rs has
  the Newton loop and the fixed-point/Anderson loop, mirroring
  sunnonlinsol_*.c control flow exactly); core NewtonSolver/
  FixedPointSolver hold only state/counters.
- `fn_implicit` C alias is modeled as enum `FnImplicitAlias
  {None,Fi0,Tempv5,ArkFn}` in arkode_arkstep_impl.rs.
- Xvecs (C's scratch array of N_Vector pointers) cannot exist in safe
  Rust: operand lists are assembled at call sites; the liw accounting
  for nfusedopvecs is kept, **but only added when cvals is first
  allocated** (C adds it once; ReInit must not re-add — bug found via
  ark_KrylovDemo_prec workspace printout).

## 2. FP-exactness rules that made 28/28 outputs byte-identical

- `linear_sum_with(a, b, y)` == `z = a*z + b*y` with C's special-case
  branches (a==b => a*(z+y); a==-b => a*(z-y)).  Use it whenever the C
  N_VLinearSum aliases z with an operand; use free `N_VLinearSum`
  otherwise.  When C's kernel picks VScaleDiff with the NON-self operand
  first (z = 1*(x - z)), write the explicit element loop — see the
  lsrkstep yerr computations.
- `N_VLinearCombination` free fn = element-major acc, bit-identical to
  C's vector-major for distinct destinations.  For z==X[0]:
  c0==1 => accumulate variant (erk_accumulate_forcing pattern);
  c0!=1 => `lsrk_lincomb_inplace` (z *= c0 then vector-major adds).
- IEEE facts relied on (safe): x+y commutes bitwise; 1.0*x == x;
  -(a-b) == b-a EXCEPT for signed zero (why the explicit-loop rule
  above exists).
- `SUNRpowerR` is PLAIN pow in 7.7.0 (no base<=0 guard).  Soderlind
  controller depends on pow(0, negative)=+inf flowing through clamps.
- C variable-reuse quirks are replicated as straight-line code with a
  comment (ARKodeSPRKTable_ToButcher outer loop executes once).

## 3. Stale shipped references / LOCAL-C mechanism

- Several shipped `.out` files predate 7.7.0 formatting/behavior
  (SUN_TABLE_WIDTH 28->29 for kepler; adaptivity drift for lsrk).
  The harness classifies a run as `LOCAL-C` when it differs from the
  shipped ref but is byte-identical to `localref/<solver>/<dir>/<name>.out`.
- ALWAYS suspect a stale ref when: solution rows match but the stats
  block differs, or step counts differ by ~1 late in a long run.
  Confirm against a local C build BEFORE debugging the port.
- `tools/verify_args.map`: `<ref-basename> <argv...>` overrides the
  underscore->space arg decoding (needed when keys contain underscores).
- Harness variant scan: refs prefixed by a LONGER example name are
  skipped ($names newline fix already applied in verify_examples.sh).
